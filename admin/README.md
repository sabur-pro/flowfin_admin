# FlowFin — админка

Next.js 16 (App Router) + TypeScript в strict-режиме. Отдельное приложение,
которое ходит в FlowFin API по HTTP. Своей базы у неё нет.

## Запуск

```bash
cp .env.example .env      # укажите адрес API
npm install
npm run dev               # http://localhost:3100
```

Нужен аккаунт с ролью `ADMIN`. Зарегистрируйтесь через `POST /api/auth/register`
и повысьте роль из каталога `back`:

```bash
npm run make-admin -- you@example.com
```

## Архитектура

Зависимости направлены строго внутрь: `app` → `application` → `domain`.
Домен не знает ни про React, ни про fetch, ни про Next.

```
src/
├── domain/           бизнес-правила и типы. Чистый TypeScript, без зависимостей
│   ├── unit-economics/   модель подписки: рынки, каналы, налоги, проекция
│   ├── users/            состояние доступа аккаунта
│   └── finance/          сводка по кассе
├── application/      сценарии использования и порты (интерфейсы)
│   ├── ports/            что приложению нужно от внешнего мира
│   └── use-cases/        собственно операции, зависят только от портов
├── infrastructure/   реализация портов: HTTP-шлюзы, сессия, композиционный корень
└── presentation/     React-компоненты и форматирование
    app/              роуты Next, тонкий слой поверх сценариев
```

Один и тот же расчёт юнит-экономики выполняется и на сервере при рендере, и в
браузере при движении ползунка — потому что это чистые функции без побочных
эффектов.

## Разделы

- **Обзор** — размер базы, конверсия в подписку, касса за 90 дней.
- **Пользователи** — поиск и фильтры по состоянию доступа. Подписка считается
  активной, пока не истёк оплаченный период: фоновой задачи, которая гасит
  просроченные, в API нет.
- **Финансы** — платежи AlifPay: по тарифам, способам оплаты и дням. Раздел
  заготовлен под другие провайдеры, структура данных для этого готова.
- **Юнит-экономика** — интерактивная модель: юрисдикция продавца (Дубай или
  Таджикистан) × рынок покупателя (Таджикистан, СНГ, Европа, США, Залив) ×
  канал продаж. Считает маржу с подписчика, LTV, окупаемость CAC и P&L на три
  года с корректным налогом: раз в год, с переносом убытков и необлагаемой
  суммой.

## Безопасность

Токен доступа лежит в `httpOnly`-куке и в клиентский бандл не попадает: все
запросы к API уходят с сервера. `proxy.ts` отсекает анонимные запросы на краю,
но настоящая проверка роли — в `requireAdminContext` и в самом API, где
`/api/admin/*` закрыт связкой `AuthGuard('jwt')` + `RolesGuard` + `@Roles(ADMIN)`.
